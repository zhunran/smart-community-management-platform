# 物业管理系统 - 关键实现逻辑

## 一、框架层（property-framework）

### 1.1 JWT 双 Token 鉴权机制

**核心文件**：[JwtUtil.java](file:///d:/.workspace/javaproject/property-management-system/property-management/property-framework/src/main/java/com/property/framework/web/security/JwtUtil.java)、[TokenService.java](file:///d:/.workspace/javaproject/property-management-system/property-management/property-framework/src/main/java/com/property/framework/web/security/TokenService.java)

- **Access Token**（短效，HMAC-SHA512 签名）：携带完整用户信息（userId、username、realName、role），用于业务请求鉴权。claims 中 `type=access`。
- **Refresh Token**（长效，仅含 userId）：claims 中 `type=refresh`，`getLoginUser()` 校验 type 必须为 `access`，防止 Refresh Token 被误用于业务请求。
- **签发流程**（`TokenService.issue()`）：登录成功 → 签发双 Token → Refresh Token 存入 Redis（key：`token:refresh:{role}:{userId}`，TTL 与 Refresh Token 一致）。
- **刷新流程**（`TokenService.refresh()`）：校验签名有效 + type=refresh + 与 Redis 中存储一致 → 重新生成 Access Token。
- **登出流程**（`TokenService.logout()`）：删除 Redis 中的 Refresh Token → 将 Access Token 加入黑名单（key：`token:blacklist:{token}`，TTL = Access Token 剩余有效期）。黑名单旁路操作失败不影响主流程。
- **Cookie 策略**：Token 通过 httpOnly Cookie 传输，避免 XSS 窃取。管理端和业主端使用不同的 Cookie 路径（`/api/admin/auth/refresh` vs `/api/owner/auth/refresh`），防止互相覆盖。

### 1.2 请求鉴权拦截器

**核心文件**：[AuthInterceptor.java](file:///d:/.workspace/javaproject/property-management-system/property-management/property-framework/src/main/java/com/property/framework/web/interceptor/AuthInterceptor.java)

- 优先从 `Authorization: Bearer xxx` 请求头提取 Token，其次从 Cookie 读取。
- `@SkipAuth` 注解可标注在方法或类上，方法级优先级高于类级。
- 黑名单检查：已登出的 Access Token 直接拒绝。
- 解析成功后通过 `SecurityUtil.setLoginUser()` 存入 ThreadLocal。
- 请求结束后在 `afterCompletion` 中清理 ThreadLocal。

### 1.3 操作日志异步落库

**核心文件**：[OperationLogAspect.java](file:///d:/.workspace/javaproject/property-management-system/property-management/property-framework/src/main/java/com/property/framework/web/aspect/OperationLogAspect.java)

- 拦截 `@OperationLog` 注解的方法，使用单线程守护线程池异步写入 `t_sys_operation_log` 表。
- 主线程采集上下文快照（request、traceId、loginUser），因为 RequestContextHolder 和 ThreadLocal 在异步线程中不可用。
- 落库失败不影响主流程，异常被静默吞掉。

### 1.4 全局异常处理

**核心文件**：[GlobalExceptionHandler.java](file:///d:/.workspace/javaproject/property-management-system/property-management/property-framework/src/main/java/com/property/framework/web/advice/GlobalExceptionHandler.java)

- 覆盖 12 种异常类型，统一返回 `ApiResult` 格式。
- 参数校验异常（`MethodArgumentNotValidException`、`BindException`、`ConstraintViolationException`）统一返回 `PARAM_ERROR`，拼接字段级错误信息。
- 对 `favicon.ico` 和 `.well-known` 等浏览器自动请求跳过日志记录，减少噪音。

### 1.5 统一响应包装

**核心文件**：[ResponseAdvice.java](file:///d:/.workspace/javaproject/property-management-system/property-management/property-framework/src/main/java/com/property/framework/web/advice/ResponseAdvice.java)

- 跳过 `String`、`Resource`、文件流等不适用包装的返回类型。
- 跳过 Swagger/SpringDoc 路径，避免干扰 API 文档生成。

### 1.8 Redis 分布式锁

## 四、账单模块（property-module-bill）

### 3.1 四种计费方式

**核心文件**：[BillServiceImpl.java](file:///d:/.workspace/javaproject/property-management-system/property-management/property-module-bill/src/main/java/com/property/module/bill/service/impl/BillServiceImpl.java)

| 计费方式 | calcType | 计算公式                                     |
| -------- | -------- | -------------------------------------------- |
| 按面积   | 1        | `房屋面积 × 单价 × 月数`                     |
| 按户     | 2        | `单价 × 月数`                                |
| 按用量   | 3        | `100（预估） × 单价`（无抄表数据时默认 100） |
| 固定金额 | 4        | `单价`                                       |

- 月数映射：月=1、季=3、半年=6、年=12。
- **单价优先级**：费用标准覆盖（`FeeStandard` 按 `roomId:feeItemId` 匹配，且 `startDate <= billDate <= endDate`）> 费用项默认单价。

### 3.2 账单生成幂等性

- 同一房屋同一账期，若已有非终态账单（排除状态为已作废/已减免/已缴清），则跳过不重复生成。
- 账单编号：`BILL + yyyyMMdd + 4位流水`。

### 3.3 账单状态机

**核心文件**：[BillStatusEnum.java](file:///d:/.workspace/javaproject/property-management-system/property-management/property-module-bill/src/main/java/com/property/module/bill/enums/BillStatusEnum.java)

```
UNPAID(0) ──缴费──► PARTIAL(1) ──缴费──► PAID(2)
    │                  │
    └──逾期标记────────┘
    │
    ▼
OVERDUE(5) ──缴费──► PARTIAL(1) / PAID(2)

终态：PAID(2)、VOIDED(3)、DISCOUNTED(4) —— 不可再缴费
可缴费状态：UNPAID(0)、PARTIAL(1)、OVERDUE(5)
```

- `computeAfterPayment(paidAmount, totalAmount)`：根据已缴金额自动计算新状态（≥total→PAID，>0→PARTIAL，=0→UNPAID）。

### 3.4 整单缴费与分项缴费

- **整单缴费**（`manualPayment`）：仅支持现金/转账，计算待缴金额 → 生成支付单号 → 插入支付记录 → 更新账单 `paidAmount` → 调用 `BillItemAllocator` 按明细顺序分摊已缴金额到各明细。
- **分项缴费**（`itemizedPayment`）：校验每笔金额 ≤ 该明细待缴金额 → 原子更新 `SET paid_amount = paid_amount + #{amount}` → 更新账单总已缴金额和状态。
- 并发安全：`selectByIdForUpdate` 提供行级锁（`SELECT ... FOR UPDATE`），防止并发超收。

### 3.5 逾期机制

- `BillMapper.selectOverdueBills`：扫描 `due_date < today` 且 status IN (0,1,5) 的账单。
- `markAsOverdue`：标记为 status=5，计算罚息（未缴金额 × 日利率 × 逾期天数，上限 100%）。
- OVERDUE 状态仍可缴费。

**核心文件**：[AlipayService.java](file:///d:/.workspace/javaproject/property-management-system/property-management/property-module-payment/src/main/java/com/property/module/payment/service/AlipayService.java)、[PaymentOrderService.java](file:///d:/.workspace/javaproject/property-management-system/property-management/property-module-payment/src/main/java/com/property/module/payment/service/PaymentOrderService.java)

### 5.2 异步回调防重机制（三重防护）

**核心文件**：[PaymentCallbackService.java](file:///d:/.workspace/javaproject/property-management-system/property-management/property-module-payment/src/main/java/com/property/module/payment/service/PaymentCallbackService.java)、[PaymentCallbackTxService.java](file:///d:/.workspace/javaproject/property-management-system/property-management/property-module-payment/src/main/java/com/property/module/payment/service/PaymentCallbackTxService.java)

| 层级         | 机制                                  | 实现                                          |
| ------------ | ------------------------------------- | --------------------------------------------- |
| **分布式锁** | Redis `SET NX EX`                     | `lock:payment:callback:{paymentNo}`，30s 超时 |
| **行级锁**   | MySQL `SELECT ... FOR UPDATE`         | 串行化并发回调                                |
| **乐观锁**   | `UPDATE ... WHERE payment_status = ?` | `affectedRows=0` 则失败                       |
| **幂等检查** | 终态直接返回                          | 已到达终态不重复处理                          |

回调流程：

```
异步通知 POST → 验签（RSA2）→ 仅处理 TRADE_SUCCESS/TRADE_FINISHED
→ Redis 分布式锁 → 行级锁（FOR UPDATE）→ 幂等检查（终态跳过）
→ 状态机校验（canTransitionTo）→ 乐观锁更新支付记录
→ 更新账单 paidAmount + 重新计算状态 → 分摊到明细
→ finally 释放 Redis 锁
```

### 5.3 主动对账补偿

**核心文件**：[PaymentReconciliationService.java](file:///d:/.workspace/javaproject/property-management-system/property-management/property-module-payment/src/main/java/com/property/module/payment/service/PaymentReconciliationService.java)

### 15.1 Token 刷新机制

**核心文件**：[request.ts](file:///d:/.workspace/javaproject/property-management-system/property-management/property-admin-web/src/utils/request.ts)

- 响应拦截器在收到 401 时触发静默 Token 刷新。
- **并发去重**：多个并发 401 只触发一次刷新请求，其他请求排队等待（`refreshing` 标志 + `waiters` 回调数组）。
- 刷新成功 → 用新 Cookie 重试原请求；失败 → 跳转登录页。

### 15.2 路由守卫
