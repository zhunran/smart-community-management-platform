## 二、Maven 模块组织

共 15 个 Maven 子模块，按职责分为四层：

### 2.1 公共层

| 模块               | ArtifactId | 职责                                                                                                                            |
| ------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------- |
| property-common    | 公共模块   | 纯数据定义：`ApiResult`、异常体系、DTO、枚举。无任何业务逻辑，仅依赖 Lombok                                                     |
| property-framework | 框架模块   | 基础设施层：JWT 鉴权、拦截器、AOP 切面、全局异常处理、统一响应包装、配置类、Redis 工具、系统配置服务、系统用户（SysUserEntity） |

### 2.2 业务模块层

| 模块                         | ArtifactId | 职责                                                           |
| ---------------------------- | ---------- | -------------------------------------------------------------- |
| property-module-housing      | 房产模块   | 楼栋、单元、房屋数据访问层，统一为其他模块提供房屋数据查询服务 |
| property-module-bill         | 账单模块   | 费用项、费用标准、账单、支付记录、仪表盘统计                   |
| property-module-owner        | 业主模块   | 业主信息、房屋绑定、家庭成员、车辆、投诉建议                   |
| property-module-payment      | 支付模块   | 支付宝支付、回调处理、支付对账                                 |
| property-module-parking      | 车位模块   | 车位信息、使用记录、租赁合同、双轨对账预警                     |
| property-module-notification | 通知模块   | 公告管理、邮件发送                                             |
| property-module-statistic    | 统计模块   | 收费趋势、操作审计                                             |
| property-module-ai           | AI 模块    | AI 客服对话、工具函数                                          |
| property-module-community    | 社区模块   | 社区活动、活动报名、邻里论坛（帖子/评论/点赞）、投票问卷       |
| property-module-lifeservice  | 便民服务   | 报修工单（8 态流转）、场地预约（冲突检测/月上限）、访客通行码  |

### 2.3 入口层

| 模块               | ArtifactId | 端口 | 说明                                                               |
| ------------------ | ---------- | ---- | ------------------------------------------------------------------ |
| property-admin-api | 管理员 API | 8081 | 管理后台 REST API 入口，聚合所有业务模块，含 `@Scheduled` 定时任务 |
| property-owner-api | 业主 API   | 8084 | 业主端 REST API 入口，权限隔离，仅暴露业主相关功能                 |
| property-task      | 定时任务   | 8083 | XXL-Job 执行器，独立部署运行自动化任务                             |

### 2.4 前端层（非 Maven 模块）

| 项目               | 技术栈               | 说明              |
| ------------------ | -------------------- | ----------------- |
| property-admin-web | Vue 3 + Element Plus | PC 端管理后台 SPA |
| property-owner-web | Vue 3 + Vant         | 移动端业主端 H5   |

## 三、模块依赖关系

```
property-common (Lombok)
      │
      ▼
property-framework (Web, JWT, Redis, Swagger, MyBatis-Plus, AOP, Security Crypto, SysUser)
      │
      ├──► property-module-housing
      ├──► property-module-bill           ──► property-module-housing, property-module-owner
      ├──► property-module-owner
      ├──► property-module-payment        ──► property-module-bill
      ├──► property-module-parking
      ├──► property-module-notification
      ├──► property-module-statistic      ──► property-module-bill
      ├──► property-module-ai             ──► bill, owner, parking, notification
      ├──► property-module-community      ──► (无模块内依赖)
      ├──► property-module-lifeservice    ──► (无模块内依赖)
      │
      ├──► property-admin-api            ──► 所有 module
      ├──► property-owner-api            ──► bill, owner, housing, payment, parking, notification, ai, community, lifeservice
      └──► property-task                 ──► bill, payment, owner, notification
```

所有模块依赖关系为**单向**：业务模块 → framework → common。入口层聚合所有需要的业务模块。

## 四、分层架构设计

### 4.1 后端分层（每个模块内部）

```
Controller 层  ──►  REST API 入口，参数校验，调用 Service
     │
Service 层    ──►  业务逻辑编排，事务管理
     │
Mapper 层     ──►  数据访问（MyBatis-Plus BaseMapper + 自定义 SQL）
     │
Entity 层     ──►  数据库实体映射
```

### 4.2 框架层（framework）提供的横切能力

| 能力              | 实现方式                                              | 文件                    |
| ----------------- | ----------------------------------------------------- | ----------------------- |
| JWT 双 Token 鉴权 | JwtUtil + TokenService + SecurityUtil                 | `web/security/`         |
| 请求鉴权拦截      | AuthInterceptor（支持 @SkipAuth 跳过）                | `web/interceptor/`      |
| 链路追踪          | TraceFilter（traceId 生成与传递）                     | `web/filter/`           |
| 操作审计日志      | @OperationLog + OperationLogAspect（异步落库）        | `web/aspect/`           |
| 请求日志          | WebLogAspect（自动记录入参/出参/耗时）                | `web/aspect/`           |
| 全局异常处理      | GlobalExceptionHandler（12 种异常类型）               | `web/advice/`           |
| 统一响应包装      | ResponseAdvice（非 ApiResult 自动包装）               | `web/advice/`           |
| 跨域配置          | CorsConfig                                            | `config/`               |
| JSON 序列化       | JacksonConfig（Long→String、时间格式化）              | `config/`               |
| MyBatis-Plus      | MyBatisPlusConfig（分页、自动填充、Mapper 扫描）      | `config/`               |
| 密码加密          | PasswordConfig（BCrypt）                              | `config/`               |
| Redis             | RedisConfig（自定义序列化、CacheManager）             | `config/`               |
| API 文档          | SwaggerConfig（Knife4j 分组）                         | `config/`               |
| 系统配置          | SysConfigService（数据库配置 + Redis 缓存）           | `service/`              |
| 系统用户          | SysUserEntity + SysUserMapper（用户表实体与数据访问） | `entity/` `repository/` |
| Redis 工具        | RedisUtil（KV、原子计数、分布式锁）                   | `util/`                 |

### 4.3 前端分层

```
Views（页面）         ──►  业务页面组件
     │
API（接口封装）       ──►  后端 API 调用封装（15 个模块）
     │
Utils（工具）         ──►  Axios 实例、Token 刷新、请求拦截
     │
Router（路由）        ──►  路由配置 + 守卫（登录态校验）
     │
Store（状态管理）     ──►  Pinia（用户信息持久化）
     │
Layout（布局）        ──►  侧边栏 / TabBar 布局
     │
Components（组件）    ──►  公共组件（CountUp 等）
```

## 五、部署架构

```
┌─────────────────────────────────────────────────────┐
│                    Docker Compose                    │
│                                                      │
│  ┌──────────┐  ┌──────────────────────────────────┐ │
│  │  Nginx   │  │  后端服务（3 个独立进程）           │ │
│  │  :80     │  │  ┌──────────┐ ┌──────────┐       │ │
│  │  反向代理 │──┤  │ admin-api│ │ owner-api│       │ │
│  │  静态资源 │  │  │ :8081    │ │ :8084    │       │ │
│  └──────────┘  │  └──────────┘ └──────────┘       │ │
│                │  ┌──────────┐                     │ │
│                │  │ task     │                     │ │
│                │  │ :8083    │                     │ │
│                │  └──────────┘                     │ │
│                └──────────────────────────────────┘ │
│  ┌──────────┐  ┌──────────┐  ┌──────────────┐     │
│  │  MySQL   │  │  Redis   │  │ XXL-Job Admin│     │
│  │  :3306   │  │  :6379   │  │ :9099        │     │
│  └──────────┘  └──────────┘  └──────────────┘     │
└─────────────────────────────────────────────────────┘
```

三个后端服务可独立部署，共享同一个 MySQL 和 Redis 实例。XXL-Job 调度中心统一管理定时任务。Nginx 作为统一入口，代理前端静态资源并反向代理后端 API。

## 六、关键设计决策

1. **双 Token 机制**：Access Token（短效，含完整用户信息）+ Refresh Token（长效，仅含 userId，存 Redis），支持无感刷新，登出时 Access Token 加入黑名单。

2. **httpOnly Cookie 传输 Token**：前端不直接存储 Token，防止 XSS 攻击窃取。AuthInterceptor 优先从 Authorization Header 读取，其次从 Cookie 读取。

3. **入口隔离**：管理端（admin-api）和业主端（owner-api）独立部署，使用不同的 JWT 密钥，业主端 API 自动过滤当前用户数据实现权限隔离。

4. **操作日志异步落库**：OperationLogAspect 使用单线程守护线程池异步写入，不阻塞业务请求，落库失败不影响主流程。

5. **支付幂等与防重**：支付宝回调处理使用 Redis 分布式锁 + 数据库行级锁（FOR UPDATE）+ 乐观锁三重防护，确保不重复处理。

6. **Long 转 String 序列化**：Jackson 配置中将所有 Long 类型转为字符串，解决前端 JavaScript 精度丢失问题。
