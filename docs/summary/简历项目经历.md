## 二、项目简介（一句话版）

> 面向物业管理方与业主的一体化物业运营平台，覆盖「资源管理 → 计费 → 收缴 → 催缴 → 对账 → 审计 → AI 客服」完整业务闭环，实现物业日常运营的自动化、在线化与可追溯。

**详细版：**

该系统是一套前后端分离的物业管理系统，包含 PC 端管理后台与移动端业主端两个入口，管理端负责房产业主档案、费用设置、账单管理、支付对账与经营审计，业主端提供自助查账、在线缴费、车位办理与 AI 智能咨询。系统通过 JWT 双 Token 实现两端身份隔离鉴权，对接支付宝完成在线缴费，借助 XXL-Job 定时任务自动化完成账单生成、逾期扫描与催缴，并引入 Redis 分布式锁、MySQL 行级锁、乐观锁等机制保障资金场景的数据一致性。

## 四、个人职责与工作内容

> 建议挑选与目标岗位最匹配的 4～6 条写入简历，每条遵循「做了什么 + 用什么技术 + 解决什么问题/达到什么效果」。

### 架构设计
1. 独立设计并落地 **12 个 Maven 模块**的前后端分离架构，划分公共层（common）、框架层（framework）、业务层（bill/owner/payment/parking/notification/statistic/ai）、入口层（admin-api/owner-api/task），实现管理端与业主端**工程级隔离**，各自独立部署、独立鉴权，权限边界清晰。
2. 在框架层沉淀统一横切能力：**JWT 双 Token 鉴权、@SkipAuth 注解式放行、全局异常处理（12 种异常）、@OperationLog 异步审计日志、ResponseAdvice 统一响应包装、链路追踪 TraceFilter**，业务模块零重复开发。

### 鉴权与安全
3. 设计并实现 **JWT 双 Token 机制**（短效 Access Token + 长效 Refresh Token），Refresh Token 存 Redis 支持服务端随时吊销；采用 **httpOnly Cookie 传输**防 XSS 窃取，登出时 Access Token 加入 Redis 黑名单实现即时失效。
4. 采用「**默认全拦截 + @SkipAuth 注解放行**」的 fail-closed 鉴权模式，方法级优先级高于类级，避免 URL 白名单漏配风险。

### 账单与并发控制
5. 实现 **4 种计费方式**（按面积/按户/按用量/固定金额）的抽象计价模型（calcType），通过**幂等生成**（同房屋同账期非终态账单跳过）避免账单重复，账单状态机严格约束流转。
6. 针对不同风险场景**分级选锁**：资金缴费/支付回调使用 **Redis 分布式锁 + SELECT FOR UPDATE 行级锁 + 乐观锁**多重防护防超收；车位绑定/变更使用乐观锁（@Version）控制并发冲突，在性能与正确性间权衡。

### 支付与对账
7. 对接**支付宝电脑网站支付与手机网站支付**（按 User-Agent 自动识别设备分流），处理异步通知 RSA2 验签与交易查询。
8. 设计**支付回调多重防重**（分布式锁 → 行级锁 → 乐观锁 → 幂等检查）与**主动对账补偿**（扫描 30 分钟前待确认订单逐条查证），解决「回调重复/丢失导致账实不符」的资金一致性问题。

### 定时任务与自动化
9. 基于 **XXL-Job** 实现账单生成、逾期扫描、逾期邮件催缴、支付对账四个自动化任务，罚息等参数存入 `sys_config` 支持热配置。

### AI 客服
10. 集成 **Spring AI + Function Calling**，用 `@Tool` 工具函数让 AI 可查询真实账单/房屋/公告数据（而非编造），通过 **SSE 流式输出**实现打字机效果，替代业主高频重复咨询。

## 五、项目亮点与难点（面试可展开）

1. **双 Token + httpOnly Cookie + 黑名单**：解决「长期有效 Token 易泄露 vs 短效 Token 体验差」的矛盾，以及 Token 登出后即时失效问题。
2. **按风险分级选锁**：金额场景（缴费/支付）用悲观锁 + 分布式锁多重保护，车位场景用乐观锁，体现「根据冲突后果严重程度选择并发策略」的工程判断。
3. **支付「至少一次投递、恰好一次生效」**：回调重复与丢失是资金系统致命问题，用「被动回调 + 主动对账补偿」双保险保证最终一致。
4. **fail-closed 鉴权**：默认拒绝 + 注解放行，比 URL 白名单更安全、更易维护。
5. **Long → String JSON 序列化**：解决前端 JS 精度丢失问题。
6. **SSE 替代 WebSocket**：AI 回复为单向流式，SSE 更简单、易穿透代理、自动携带 httpOnly Cookie，选型更贴合场景。
7. **异步审计日志**：单线程守护线程池旁路落库，不阻塞主业务流程且保证写入顺序。
