## 一、单元/集成测试重点

### 1.1 community 模块

| 用例                              | 预期                                                                |
| --------------------------------- | ------------------------------------------------------------------- | --- |
| 报名：正常报名                    | signup 插入成功，signup_count+1                                     |
| 报名：重复报名                    | 抛业务异常"已报名"                                                  |
| 报名：并发 50 线程抢最后 1 个名额 | 仅 1 人成功，其余乐观锁失败可重试，signup_count 不超上限            |
| 取消报名后再报名                  | 允许（唯一索引排除已取消记录）                                      |
| 满员自动流转                      | signup_count 达上限时活动状态变"已满员"                             |
| 活动取消后报名                    | 拒绝（状态校验）                                                    |
| 发帖：内容干净                    | 直接发布 status=1                                                   |
| 发帖：含敏感词                    | status=0 进待审核，命中词写入 t_forum_post.sensitive_words 字段     |
| 评论两级组装                      | 一级按时间排序，子评论挂对父节点                                    |
| 评论两级：0 评论                  | 返回空数组，不报错                                                  |
| 评论两级：仅二级评论（一级被删）  | 孤儿评论不展示，或标记"原评论已删除"                                |
| 评论两级：含已删除评论            | status=2 的评论不在结果中出现                                       |
| 点赞 toggle                       | 调两次回到初始计数，无脏数据                                        |
| 点赞帖子后被删除                  | 点赞记录保留（物理表），前端展示时帖子不存在则忽略                  |
| 删自己的帖                        | 成功；删他人帖                                                      | 403 |
| 活动取消后 signup_count 回退      | 取消活动时，已报名记录状态不变，signup_count 不清零（保留历史数据） |
| 投票重复提交（二期）              | 唯一索引拦截，返回"已投过"                                          |

### 1.2 service（lifeservice）模块

| 用例                   | 预期                                                 |
| ---------------------- | ---------------------------------------------------- |
| 工单提交               | 生成 RP 单号，状态 0                                 |
| 状态流转合法性         | 待审核态调"接单"接口 → 拒绝                          |
| 双管理员同时审核同一单 | FOR UPDATE 串行，第二人收到"状态已变更"              |
| 业主取消限制           | 仅 0/1 态可取消，2 态取消被拒                        |
| 评价限制               | 仅 4 态可评价，重复评价被拒                          |
| 评价后修改评价         | 不允许（已评价态不可回退，防止刷分）                 |
| 超时任务               | 造 25h 前待审核单 → 扫描后 timeout_flag=1            |
| 场地冲突（二期）       | 同场地同日 10:00-11:00 已约，再约 10:30-11:30 → 拒绝 |
| 场地相邻不冲突（二期） | 已约 10:00-11:00，再约 11:00-12:00 → 成功            |
| 月度上限（二期）       | 超过 monthly_limit → 拒绝                            |
| 通行码核销（二期）     | 有效期内通过且 used_count+1；过期拒绝；超次数拒绝    |

## 二、接口测试（Apifox/Swagger）

1. 全接口过一遍正常路径
2. 越权测试：业主 A 的 token 访问业主 B 的工单/帖子删除 → 403
3. 未登录访问 → 401（@SkipAuth 只加在无需登录的列表类接口，**默认拦截**）
4. 参数校验：缺必填、超长、非法枚举值 → 400 + 明确 message

## 四、性能与容量预估

| 场景         | 预估量级                                          | 结论                                                             |
| ------------ | ------------------------------------------------- | ---------------------------------------------------------------- |
| 帖子列表 QPS | < 50                                              | 单表 + 索引足够                                                  |
| 报名瞬时并发 | 单活动 < 200                                      | 乐观锁重试可承受                                                 |
| 点赞写 QPS   | < 100                                             | 单行更新无热点（分散在各帖子）                                   |
| 工单日增     | < 500                                             | 无需分表                                                         |
| 图片存储     | 单张 ≤ 5MB，总量预估 < 50GB（1000+ 业主活跃一年） | 本地磁盘第一年可支撑，后续迁移 OSS。图片命名按日期分目录便于归档 |

超出预估的演进路径（记录，不在本期实施）：帖子列表加 Redis 缓存 5 分钟、图片迁 OSS、comment 表按年归档。
